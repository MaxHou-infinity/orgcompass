# 文档索引

本目录**刻意分成「公开」与「内部归档」两类**，边界如下。

## 公开（随仓库提交）

| 目录 / 文件 | 内容 |
|---|---|
| `assets/` | README 用视觉资产（截图、流程图、社交预览图） |
| `design/` | v2.0.x 交互与视觉设计记录（v201 / v202 / v203 / v208 系列） |
| `releases/` | 各版本发布说明（v2.2.1 起） |
| `github-repository-settings-checklist.md` | 仓库设置清单 |

## 内部归档（**已 gitignore，不提交**）

本目录下**以版本号开头**的文档（`v211-*.md`、`v220-*.md`、`v230-*.md`、`v231-*.md`、
`v232-*.md`、`v240-*.md`、`v300-requirements.md` 等）以及 `review-assets/`，
都是**迭代期的内部路线图 / 契约 / 审计 / 验收材料**，仅保留在本地。

`.gitignore` 按「版本周期」逐条添加忽略规则（每条都带注释说明是哪一版的归档），
这是有意为之：版本周期一眼可辨，且新增周期时必须显式加一条规则，
不会因为"放错目录"而把内部规划误提交到公开仓库。

> 因此：**不要把内部文档移进 `design/`**（那会绕过忽略规则）。
> 新增内部文档时，直接用「版本号前缀 + 放在 `docs/` 根」的既有约定，并在 `.gitignore` 补一条规则。
