# OrgCompass v2.3.2｜导入契约重定义与画布可读性

v2.3.2 重新定义了「数据怎么进来」与「画布怎么读」：**员工信息表成为画布的唯一主结构来源**，组织架构表降级为可选补充层；同时修复了一批会静默破坏用户数据的路径，并把此前看不见的问题搬到了界面上。

> **向后兼容声明**
> - **`.orgproj` 文件格式保持 4，不新增必填字段。** v2.3.2 可无损读取 v2.3.0 / v2.3.1 生成的文件；v2.3.2 生成的文件也能被 v2.3.1 读取（新增的 `levelConfigs`、`orgTemplates` 均为可选字段，旧版会原样保留而不丢数据）。
> - **旧 Excel 无需改造**：`岗位名称` / `职位` 仍可读取；`一级部门` 由必填列放宽为可选列。
> - **本版会改变部分用户看到的内容**（详见下）。多数是「把错的改对」或「把看不见的变可见」，不是数据出错。

## 导入：员工表即架构图

- 上传员工信息表即可生成完整组织架构图，不再需要先准备组织架构表。
- **组织架构表降级为「补充层」**：只补两件员工表装不下的事 —— 没有任何员工的空部门、部门负责人。并且**改为原地合并**，员工 / 岗位 / 编制 / 评分 / 任职记录全部不受影响。
  - ⚠️ 旧实现会用模板重建整棵树，副作用是**把所有岗位编制清零、评估数据一起被冲掉**。
- 重复上传组织架构表按「可替换」处理：先收回上一份模板留下的空部门，结果恒为「员工表 + 新模板」，不再无限叠加。
- **「岗位」与「岗位名称」合并为一列**（旧列名兼容读取）；空值不再落 `NA` —— 此前画布上会真的显示 "NA"，把「用户没填」显示成「岗位叫 NA」。
- 部门列按「**列位置 = 声明层级**」建树：修复「二级留空导致三级部门被压成二级，并与组织模板产生两个同名空部门」。
- **重导入不再清零编制**：按「部门路径 + 岗位名」继承编制 / 序列 / 职级带宽 / 状态。
- 导入后一次性说清：几人未分配部门、几个部门层级断档、几行岗位两列取值冲突、几人职级未在配置中。

## 层级断档（向上无归属）三重可见

员工的部门列中间留空时（如只填一级与三级），该部门向上没有归属。此前无感知，现在：

- 连线上以**琥珀色虚线**标出「这段父子关系是断的」；
- 部门卡头部给出 **「缺 L2」胶囊**，悬停解释缺哪一级、当前挂在哪、怎么修；
- 诊断报告生成一条可行动建议。

## 画布可读性

- **卡片宽度 220 → 320px**，岗位行改为单行不换行 + 「**在岗 N**」胶囊。
  - 修复「岗位数量全是 0」：真正的在岗人数此前被挤成竖排、不可读，用户只看到编制输入框里的 0。
- **引导线不再纵穿卡片**：层间步进新增运行期实测校正。此前岗位行实际渲染 74px 而代码按 40px 估算，每层都算矮，子部门被摆进父卡内部、连线被父卡盖住。
- 一~六级部门表头各自配色（旧实现四级往下与一级同色，层级区分不出来）。

## 备份与恢复

- 侧栏「数据备份 (.orgproj)」旁新增「**从 .orgproj 恢复**」——此前恢复入口藏在四步深处，用户反映「备份了之后没有办法恢复」。
- 备份**文件名带时间戳**（旧实现固定同名，多次备份互相覆盖、无法分辨）。
- **拒绝非项目文件**：旧实现接受任意 JSON 并把工作区静默换成空的。
- 恢复后给出「N 个场景 · N 个部门 · N 名员工 · N 个岗位」摘要；空工作区禁止导出空备份。
- 组织架构模板写入工作区级（旧实现只存内存，关闭应用即丢失）。

## 职级配置

- **职级配置提升为工作区级**：颜色 / 标签 / 成本不再随场景切换而变（此前在场景 A 改完颜色，切到场景 B 会「变回去」）。
- 颜色值加固：非 6 位十六进制（如 `#fff`、`red`）此前会让卡片底色拼出非法 CSS 而**静默变全透明**。
- 「**职级未在配置中**」可见化：这些人的卡片颜色回落成灰色、**成本按 0 计**、职级分布被单独分档，而界面上此前没有任何提示。
- 职级管理显示每行「**N 人使用**」；改动或删除被引用的职级时，先给出受影响人数与姓名样例，确认后才保存。
- 移除侧栏静态「职级颜色」图例（右上角「职级管理」已覆盖同样信息，且可直接修改）。
