## 0. 一句话定位

v2.0.9 是 **「口径可信化」补丁**（对齐 v209-v300-version-plan §3），在把 4 项诊断指标「算对」的同时，交付**唯一一个新特性**：**场景差异比较 + 管理层报告**。给用户的一句话承诺：

> **现在，你不再靠肉眼切场景、逐张截图比数字，而是直接看到「基线 → 方案 A」到底变了什么、变了多少、为什么值得讨论，并一键把它变成能交给管理层的决策底稿。**

这句话里藏着三个产品动作：**看差异**（并排 + 增量 + 高亮）、**讲得清**（每项差异可追溯到部门/人员，不黑盒）、**交得出**（可导出 / 打印 / 发给管理层）。

## 1. 场景差异比较的产品形态

### 1.1 现状缺口（用户今天在干什么）

多场景能力已在 v2.0.x 存在：`Scenario` 快照 + `ScenarioSwitcher.tsx` + `ProjectModal` 可建/复制/删除/切换场景；`DiagnosticReport.tsx` 是**单场景**诊断报告。但用户要看「基线 vs 方案 A」，今天只能：

1. 手动来回切换场景、逐张截图；
2. 肉眼对照 4 项指标卡、部门明细表、组织图；
3. 自己列一张「调了什么」的清单交给管理层。

**这不是缺数据，是缺「差异被显式算出来并排在一起」的视图。** 差异比较是 v2.0.9 唯一的新特性，也是 README「Now」承诺「更直观的场景差异比较」的落地。

### 1.2 用户最需要「看什么差异」（按优先级排序）

组织调整汇报的真实问题是三句话：**调了什么、为什么调、调了会怎样**。落到产品上，用户要看四类差异，按重要性排序：

| 优先级 | 差异类型 | 用户要回答的问题 | 呈现 |
| --- | --- | --- | --- |
| ① | **四项健康指标 + 整体诊断** | 方案让组织「变健康了还是变差了」 | 并排指标卡 + 数值 Δ + 红黄绿灯号 Δ |
| ② | **部门结构差异** | 增了哪些部门、删了哪些、谁改了层级/汇报线/负责人 | 部门差异表 + 增/删/改标记 |
| ③ | **编制 / 成本 / 缺口变化** | 这方案省多少钱、补多少编制、谁空岗谁超编 | 部门级 Δ（编制/实际/缺口/缺口成本）+ 汇总 |
| ④ | **人员流动清单** | 谁换了部门、谁换了汇报线、谁新增/移除 | 人员调动清单（可导出） |

> 关键判断：**①是「看结论」，②③④是「看细节」**。用户第一眼要的是结论（四项指标 + 整体诊断 + 3~5 条关键变化），细节是点下去可追溯的，而不是铺满整屏。

### 1.3 交互与形态建议（最低交互成本）

**锚点模型（做减法，不做 N 选 M）**：

- **默认「基线 vs 当前场景」**：一个固定的「基线」锚点（默认取场景列表里第一个场景，可手动指定），右侧一个「对比目标」下拉（默认当前场景，可切到任意单个场景）。**先做「1 vs 1」，不做「N 场景自由勾选矩阵」**（见 §4）。
- **「只看差异」为默认态**：默认只显示「有变化」的行/指标；提供「显示全部」开关给想看完整表的用户。降低信息噪音是第一优先级。
- **单一入口**：在健康度抽屉（HealthDrawer）头部与顶栏各加一个「场景对比」入口；只有 ≥2 个场景时可点，单场景置灰并提示「先复制一个场景再对比」。

**三层结构（复用现有 HealthDrawer 的 L1/L2/L3 心智）**：

- **L0 结论条**（新增，最上）：一行概览——「整体健康度 基线→方案A：关注→健康」「4 项指标 2 改善 / 1 持平 / 1 恶化」「总人数 +12 · 月成本 +24.0w · 缺口 −3」。
- **L1 四项指标并排对比**：每项指标一张「基线值 → 目标值 + Δ」卡，Δ 用**方向符号（↑/↓）+ 幅度**，灯号各自标红黄绿。**不把「上升/下降」直接刷成「好/坏」**（见 §1.5 防误读）。
- **L2 部门差异表**：行 = 部门（增/删/改/不变分组），列 = 负责人 / 编制 / 实际 / 缺口 / 缺口成本 / 层级，每列给「基线 → 目标 + Δ」，结构变化（新增/删除/移动/改汇报线）单独打标。
- **L3 人员调动清单**：列出「换了部门 / 换了汇报线 / 新增 / 移除」的员工（含兼岗 `isVirtual` 与未入架构员工），每条可点回画布定位。

**差异高亮的颜色约定（关键产品决策）**：

- **方向色 ≠ 健康色**。产品已有红/黄/绿 = 健康状态语义，**不能**再让红绿同时表达「增减」。因此「增加/减少」用**中性方向色 + 符号**（建议：增加 = 蓝色 `↑`，减少 = 灰色/红色 `↓`，持平 = 灰色 `—`），**健康灯号仍用红黄绿**，两者各司其职，避免「人数下降」被误读成「变差」。

### 1.4 可追溯性（对齐「不黑盒」承诺）

每个差异点（指标 Δ、部门行、人员调动）**可点回具体部门/人员**：指标 Δ 点开看该指标的口径与明细（复用 t2 的 breakdown：中位数/极值、P50/P90/最深链、内部/外部/兼岗计数）；部门行点开定位到画布该部门；人员调动点开定位到该员工。**差异比较视图不引入任何黑盒评分**，继续只用可解释的 4 项指标 + 红黄绿灯。

### 1.5 防误读（产品红线）

差异比较**只陈述事实、不评判优劣**：它回答「变了什么」，不回答「这个方案更好吗」。产品上表现为：

- 不自动给方案打「优化/劣化」结论，不下「推荐方案 A」的断语；
- 「改善/恶化」的判断交给看的人（HRBP/管理层），工具只把「基线→目标」的事实和灯号摆清楚；
- 若用户想引导结论，通过「关键变化摘录 + 建议动作」这种**可编辑的备注**承载，而不是自动生成评语（见 §2 管理层报告）。

## 2. 管理层报告的产品范围

### 2.1 给谁看、是什么、不是什么

| 维度 | 定义 |
| --- | --- |
| **给谁看** | 管理层 / 业务负责人 / 上级（HRBP 汇报对象），是**决策讨论底稿**，不是给 HRBP 自己看的操作手册 |
| **是什么** | 一份**多场景推演决策材料**：把「基线 vs 方案 A（/B）」的差异、结论、建议动作合并成可打印/可导出的文档 |
| **不是什么** | ①不是黑盒评分或方案排名；②不是单场景的逐部门体检清单（那是现有诊断报告）；③不替代 HRBP 的口头汇报与业务背景判断 |

### 2.2 与现有「诊断报告」的区别（关键区分）

| | 现有诊断报告（v2.0.8 已有） | 管理层报告（v2.0.9 新增） |
| --- | --- | --- |
| 作用域 | **单场景**体检 | **多场景**推演决策 |
| 核心问题 | 「这个组织健康吗、哪里有问题」 | 「方案 A 相对基线改了什么、值不值得做」 |
| 结论形态 | 单组指标 + 建议 | 并排对比 + 差异 + 关键变化 + 建议动作 |
| 是否保留 | 保留（单场景体检仍用，见 §4 无回归） | 新增；在 ≥2 场景时成为「导出报告」的升级形态 |

### 2.3 建议报告正文结构（复用 DiagnosticReport §4.2 的思路 + 差异层）

> 结构沿用现有单场景报告（头 → 摘要卡 → 指标 → 口径 → 组织图 → 明细 → 建议 → 页脚）的骨架，把「指标」「明细」「建议」三段替换为**多场景对比版**，新增「关键变化」段。

1. **报告头**：项目名 · 对比场景（基线 vs 方案 A，各带 `updatedAt` 快照时间）· 生成时间 · 版本号。**场景时间戳是可比对性的前提**（见 §5 风险）。
2. **一页结论（新增，管理层 30 秒读完）**：
   - 整体健康度变化（基线 → 方案 A，红黄绿）；
   - 3~5 条「关键变化」自动摘录（按差异幅度/结构变化/灯号变化排序）；
   - 「建议动作」区（**留白给 HRBP 填**，可编辑备注，工具不自动写评语）。
3. **四项指标并排对比**：每项「基线值 → 目标值 + Δ + 灯号变化」，下方带「口径与边界」折叠块（复用并更新 `METRIC_CALIBER_NOTES`，见 t2 D.4）。
4. **部门结构差异**：增/删/改部门清单 + 汇报线/负责人变化 + 部门级 Δ（编制/实际/缺口/缺口成本）。
5. **人员调动清单**：换部门 / 换汇报线 / 新增 / 移除（含兼岗与未入架构员工）。
6. **缺口与成本汇总**：总缺口、总缺口成本、总月成本的变化，给管理层「花/省多少钱、补多少编制」的抓手。
7. **口径与边界**：说明「差异 = 目标场景 − 基线场景」「指标口径（中位数/P90/剔除后管理者比）」「只陈述差异不评判优劣」。
8. **页脚**：由 OrgCompass v{版本} 生成 · 项目 · 对比场景 · 生成时间（沿用现有页脚）。

> 导出方式与现有报告一致：**导出 PNG + 打印/导出 PDF**；差异表另支持**导出 Excel**（供管理层二次加工，见 §3）。

## 3. 面向用户的验收标准清单

> 每条 **可核对 / 可观测**，验收动作写在 `[验收]`。覆盖：差异可读性、多场景切换正确性、导出、`.orgproj` 兼容、无回归。

### 3.1 差异可读性

- **D1** 在 ≥2 个场景时，用户能在一个视图里看到「基线 vs 目标」的**四项指标并排对比**，每项显示数值 Δ 与红黄绿灯号变化，且方向（↑/↓）与健康色（红黄绿）**互不混淆**。
  - [验收] 构造「基线 3 项健康 → 方案A 2 项健康 1 项预警」，确认：Δ 方向用符号/方向色表达，健康灯号仍用红黄绿；一眼能区分「哪个指标变了」与「哪个指标不健康」。
- **D2** 默认「只看差异」：无变化的部门/指标默认折叠或置灰，用户可切换到「显示全部」。
  - [验收] 构造「方案 A 只改了 1 个部门的编制」，确认默认视图只突出该部门的差异，其余部门不干扰视线。
- **D3** 部门差异表能区分**新增 / 删除 / 移动（改层级或父级）/ 改负责人 / 改汇报线 / 编制与成本 Δ**，且每行可追溯到具体部门。
  - [验收] 分别在方案 A 里新增一个部门、删除一个部门、把某部门拖到另一父级、换负责人，逐一确认差异表正确归类并给出该部门。
- **D4** 人员调动清单列出**换部门 / 换汇报线 / 新增 / 移除**（含兼岗与未入架构员工），每条可定位到人。
  - [验收] 把 1 名员工拖到别的部门、1 人设为新负责人、1 人删除，确认清单三条都命中且可点回画布。

### 3.2 多场景切换下的差异正确性

- **S1** 切换「对比目标」场景时，对比结果**随所选目标实时重算**，且基线锚点保持不变。
  - [验收] 建「基线 + 方案A + 方案B」，分别对比「基线 vs 方案A」「基线 vs 方案B」，确认两组差异各算各的、互不串值。
- **S2** 对比视图的数据与当前场景数据**一致**（编辑后立即反映），不出现「报告显示旧值」。
  - [验收] 在方案 A 改某部门编制后立刻打开对比，确认该部门的 Δ 已更新（复用现有 `flushCurrent`/保存语义）。
- **S3** 两个场景数据不一致（如基线有编制、方案A 未配置编制，或某指标一方不可算）时，差异明确显示「无数据/不可比」，**不把缺失当 0 计算**。
  - [验收] 构造「基线有编制、方案A 未填编制」，确认空岗/缺口该行显示「无数据/不可比」而非「0」或「−N」。

### 3.3 报告导出

- **E1** 管理层报告可**导出 PNG + 打印/导出 PDF**，内容完整、不截断、含对比与口径段。
  - [验收] 打开管理层报告，导出 PNG 与打印预览，确认一页结论、指标对比、部门差异、人员清单、口径段都在。
- **E2** 差异表可**导出 Excel**（至少含：部门、变化类型、基线/目标负责人、编制/实际/缺口/缺口成本 Δ、人员调动清单）。
  - [验收] 导出 Excel 后用表格工具打开，确认列完整、Δ 可二次求和/透视，与屏幕数值一致。

### 3.4 `.orgproj` 兼容与数据安全

- **C1** 场景差异比较与管理层报告**不新增持久化字段**（差异为运行时派生），旧 `.orgproj` 打开不受影响，新建/编辑后的 `.orgproj` 也能被旧版本打开（数据模型版本不变）。
  - [验收] 用 v2.0.8 保存的项目文件在 v2.0.9 打开、做对比、再保存，确认往返一致；反向（v2.0.9 保存 → 结构可被旧版解析）不因对比功能引入破坏性字段。
- **C2** 全程本地处理：差异计算与报告生成不联网、不上传、无遥测（沿用 v2.0.8 边界）。

### 3.5 无回归（不影响单场景诊断）

- **R1** 单场景（或只有 1 个场景）时，现有**诊断报告**行为与 v2.0.8 一致，不因对比功能改变单场景报告的结构与结论。
  - [验收] 只建 1 个场景走「导出诊断报告」，确认仍是单场景报告、内容与 v2.0.8 一致。
- **R2** 健康度抽屉的 L1/L2/L3、口径「?」说明、阶段预设等**不受影响**；对比入口在单场景时置灰且不报错。
  - [验收] 单场景打开健康度抽屉，确认原功能完好、对比入口置灰并给出「先复制一个场景」提示。
- **R3** 升级后核心路径一致、关键页视觉零漂移（对齐 v2.0.8 R1/R2 纪律）。

## 4. 优先级与范围边界（做 / 推迟 / 明确不做）

### 4.1 做（v2.0.9 交付）

| # | 范围 | 说明 |
| --- | --- | --- |
| 1 | **「基线 vs 单个目标场景」差异比较视图** | 三项指标并排 + Δ、部门差异表、人员调动清单、缺口成本汇总；默认「只看差异」+「显示全部」开关 |
| 2 | **管理层报告（≥2 场景的导出升级形态）** | 一页结论 + 指标对比 + 部门差异 + 人员清单 + 缺口成本 + 口径段；导出 PNG/打印 PDF + 差异表 Excel |
| 3 | **可追溯性** | 每个差异点可点回部门/人员；指标 Δ 点开看口径明细（复用 t2 的 breakdown） |
| 4 | **不可比/无数据提示** | 场景数据不一致时明确显示「无数据/不可比」，不把缺失当 0 |

### 4.2 推迟（进 v2.1.0 或后续）

| 范围 | 理由 |
| --- | --- |
| **N 场景自由组合对比矩阵**（勾选任意场景两两/多列并排） | 属「推演视图」的深化，v2.0.9 先做「基线 vs 单目标」，多列矩阵待场景模型（v2.1.0 岗位化）稳定后再做，避免过早定型交互 |
| **场景合并 / 归档 / 版本分支** | 与「差异比较」耦合会放大状态管理复杂度；场景管理（复制/重命名/删除）v2.0.8 已够用，合并/归档留到岗位模型之后 |
| **差异的「优劣自动评判 / 方案推荐」** | 违背「只陈述事实、不黑盒评分」的产品红线（见 §1.5）；若未来要做，必须先出设计（对齐 v209-v300-version-plan §5 的「定义债先清」纪律） |
| **人员级「岗位/胜任度」维度的差异**（谁不胜任、胜任度升降） | 依赖 v2.1.0/v2.2.0 岗位与胜任度引擎，不在 v2.0.9 |

### 4.3 明确不做（边界约定，沿用 v2.0.8）

- **不新增云端同步 / 遥测 / 账号体系**；差异计算与报告生成全程本地。
- **不引入黑盒「健康评分 / 方案评分 / 方案排名」**，保持 4 项指标可解释、可追溯。
- **不引入破坏性变更**：`.orgproj` 与导出产物兼容（§3.4）。
- **不替用户下结论**：报告不自动写「推荐方案 A」评语，建议动作留白给 HRBP 填写（可编辑备注）。

## 5. 风险提示与用户话术

### 5.1 产品风险

| 风险 | 表现 | 缓解（产品要求） |
| --- | --- | --- |
| **差异过大导致误读** | 「人数 −40」被管理层当成「优化成功」，实际可能是基线含兼岗/含未入架构员工的统计口径不同 | 报告必带「口径与边界」段；方向色与健康色分离；差异用「基线→目标 + Δ」陈述，不贴「好/坏」标签 |
| **场景数据不一致** | 一方有编制、一方没填，或基线是旧快照、方案是新快照 | 差异明确显示「无数据/不可比」；报告头带每个场景的 `updatedAt` 时间戳，肉眼可辨「在比哪个版本」 |
| **口径修正叠加的「数字跳变」** | v2.0.9 同步改了口径（中位数/P90/剔除外部），用户可能误以为「场景对比算错了」或「数据变差了」 | 对比视图与报告**沿用修正后口径**（引用 t2 的 breakdown），并在口径段写清「本版本起管理幅度改用中位数」 |
| **对比视图误导「方案已拍板」** | 用户把对比结果当成「方案 A 已被工具认可」 | 报告不产生优劣结论；建议动作留白给 HRBP；页脚/口径段声明「仅陈述差异，不评判优劣」 |

### 5.2 用户话术（可直接用，不夸大）

**场景差异比较入口 / 首次使用**：
> "把「基线」和「方案 A」并排放在一起看：哪些指标变了、哪些部门增删了、谁换了汇报线，一眼看清，不用再切来切去逐张截图。"

**管理层报告**：
> "这是一份多场景决策底稿：它告诉你方案 A 相对基线改了哪些指标、动了哪些部门和人、影响多少编制和成本。它只摆事实，不替你做判断，建议动作由你填写。"

**口径与边界（防误读）**：
> "对比结果是「目标场景 − 基线场景」的差异。指标只反映结构性信号，不替代业务背景与人才判断；差异大小不等于方案优劣，请结合实际情况解读。"

**本地优先（沿 v2.0.8，不夸大）**：
> "差异计算与报告生成只在你本机完成，不会上传；导出的图片、表格与报告请在企业认可的设备与存储上妥善管理。"

> ⚠️ **避免的表达**（会反噬信任）：「方案 A 更优」「本工具推荐方案 A」「绝对无风险」——这些既违反「只陈述事实」红线，也违反 v2.0.8 已确立的「不夸大」纪律。

## 6. 与其它任务的对齐要点（供 Captain 汇总）

- **引用 t2（analytics）的 breakdown，不再算一遍**：指标 Δ（管理幅度中位数/极值、层级 P50/P90/最深链、管理者比内部/外部/兼岗）直接复用 `computeSpanBreakdown / computeDepthBreakdown / computeManagerBreakdown`（见 `docs/v209-analytics-caliber.md` §A/B/C），管理层报告与对比视图**不得重复实现计算逻辑**。
