# 组织架构设计器 v2.0.2 — 交互与视觉设计规格（UX 输出）

> 面向对象：前端设计专家（实现依据）
> 项目：`org-structure-designer-web`（React 18 + TS strict + Vite 6 + Tailwind 3 + Tauri 2）
> 范围：仅交互 + 视觉设计，**不改动 `src/` 代码**（实现由前端设计专家负责）。
> 设计基调：延续 v2.0.1 的 2026 现代 SaaS「液态玻璃 / Aurora 渐变」风格（indigo 品牌主色），本迭代在此基础上做**信息架构升级**与**状态色体系**。
> 版本目标：v2.0.2 = Phase0 数据可信层 + Phase1 决策分析层 + Phase2 体验层。

### 0.2 ⚠️ 数据模型缺口（Phase1 / 前端需补齐的数据源）

**健康度分析 L3「编制 vs 实际 vs 缺口（含成本）」需要两类目前不在数据模型里的字段**：

| 所需字段 | 用途 | 建议来源（Phase1） |
| --- | --- | --- |
| 部门编制人数 `headcount`（可空） | 算 空岗率 / 编制缺口 | ① 组织架构模板新增列「编制人数」；② 或在新建/编辑部门时配置；③ 提供「编制配置」弹窗批量设置。**推荐模板列 + 弹窗双通道** |
| 部门平均成本 `avgCost` / 或按职级成本映射：`levelCost: Record<fullCode, number>` | 算 缺口成本 / 实际成本 / 编制成本 | ① 员工信息模板新增列「月薪/成本」；② 或按职级配置成本区间（职级管理弹窗扩展一个「成本」字段）。**推荐按职级成本映射**（干净、不依赖逐人填写） |

> 若 Phase1 暂不实现编制/成本字段：健康度中心仍可展示 L1/L2（人数/职级分布/管理幅度/层级深度/管理者比/空岗率按「实际=编制」降级计算），L3 编制缺口区显示「未配置编制数据」空态 + 「去配置」引导。**本规格按「字段可空、缺省降级显示」原则编写**，避免因数据未配置而整面板不可用。

## 1. Feature A — 组织健康度分析中心

### 1.1 形态与入口

**形态：右侧滑出抽屉（Right Drawer）**，覆盖在组织图上但不离开画布，用户可对照图表。推荐理由：
1. 分析类面板与画布需**同时可读**（对照部门看指标），居中弹窗会挡住画布。
2. 2026 SaaS 分析面板惯例（Figma 右侧属性面板 / 各类 BI 侧栏）。
3. 可承载三层内容（L1/L2/L3）并容纳「导出诊断报告」主 CTA。

**视觉**：`fixed inset-y-0 right-0 w-[640px] max-w-[92vw] glass border-l border-white/40 shadow-2xl z-[80] animate-slideInRight`（入场 240ms ease-out）。背后加一层轻遮罩 `bg-slate-900/10 backdrop-blur-[2px]`（半透明，仍能隐约看到画布）；点击遮罩可收起。默认不透明度蒙层要很浅，避免完全遮挡。

**入口（三处，主 + 备 + 场景化）**：

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| **主**：顶部栏【分析】按钮 | TopBar 右侧操作组，紧邻【职级管理】 | 打开健康度抽屉（全局） |
| 备：侧边栏「分析」卡片 | Sidebar 新增一节「组织健康度」 | 同主入口 |
| 场景化：L1 部门卡片边缘「分析」角标 | DepartmentCard 头部右侧小图标（📊 / `Activity`） | 打开抽屉并**聚焦该 L1 部门**（见 1.4） |

> TopBar 分析按钮图标：lucide `Activity` 或 `HeartPulse`（w-4 h-4），文案「健康度」。样式与【职级管理】一致（次级 ghost 按钮：`text-slate-600 hover:bg-slate-100 hover:text-slate-800`），仅在有数据（`departments.length>0`）时可用。

### 1.3 L1 部门概览（看板卡片）

**单卡结构**：
```
┌ 技术部  [●健康]  ────────────┐
│ 人数 36   编制 40             │
│ 职级分布: ▂▃▅▂▁  (L1..L5 色带) │
└─────────────────────────────┘
```
- 容器：`rounded-2xl bg-white/70 backdrop-blur-xl border border-white/50 shadow-card p-4`（沿用玻璃卡片）。
- 顶部行：部门名 `text-sm font-bold text-slate-800` + 右侧状态点（整体健康度状态色，见 1.5）。部门名可点击 → 聚焦该部门在画布（`scrollIntoView` + 高亮）。
- 主数字行：`人数 36`（`text-2xl font-bold text-slate-900`）+ `编制 40`（`text-xs text-slate-500`）。
- **职级分布条**：一条横向分段色带（每段宽度 = 该职级人数占比），沿用 `LevelConfig.color`，每个色块用 `tooltip` 显示「L1.1-初级专员 × 12」。实现为 flex item 条（`h-2 rounded-full overflow-hidden`），段间 `border-white` 分隔。若某职级未配置颜色，用兜底灰 `#CCCCCC`。
- 布局：横向可滚动（`overflow-x-auto` + `flex gap-3`，卡 `min-w-[190px]`）；或网格 `grid-cols-2`。**推荐横向可滚**（部门多时不挤爆高度）。

### 1.4 聚焦单个 L1 部门（场景化入口）

- 从 L1 卡片的「分析」角标进入时：抽屉只展示该 L1 + 其子孙子树（`focusScope = 部门id`），顶部标题变为「技术部 · 组织健康度」，出现一个「查看全公司」按钮以退出聚焦（回到全局）。
- 命中判读：所有指标在该子树范围内重算。

### 1.5 状态色体系（红/黄/绿）——核心

在沿用 aurora/indigo 品牌色的同时，建立**独立、语义清晰的状态色**（用于健康度指标，避免与品牌色混淆）：

| 状态 | 语义 | Hex | Tailwind 建议 | 用途 |
| --- | --- | --- | --- | --- |
| 健康 | 达标 | `#10B981` | `emerald-500`，bg `emerald-50/70`，border `emerald-300` | 指标卡状态点 / 表格 OK 行 |
| 关注 | 偏预警 | `#F59E0B` | `amber-500`，bg `amber-50/70`，border `amber-300` | 需留意但不紧急 |
| 预警 | 需干预 | `#EF4444` | `red-500`，bg `red-50/70`，border `red-300` | 明显异常 |

**状态点样式**：`<span className="w-2 h-2 rounded-full bg-emerald-500"><span>`，旁边配状态文字（`text-xs`，`text-emerald-600` / `text-amber-600` / `text-red-600`），形成「●健康」「●关注」「●预警」。

> 说明：`emerald/amber/red` 与品牌 `indigo/violet` 色相互独立，不冲突。指标卡底色用对应状态色的 `-50/70` 淡染，保持玻璃感（`backdrop-blur`）。

### 1.6 L2 健康度指标（定义 + 阈值 + 判读）

4 个指标卡。**指标卡结构**：
```
┌ 管理幅度 ─────────────┐
│ [●健康]   5.2          │
│ 每经理平均直管 ~5 人     │
│ 带宽 3–8 健康            │
└───────────────────────┘
```
- 容器：`rounded-2xl bg-white/70 backdrop-blur-xl border border-white/50 shadow-card p-4`，顶部指标名 `text-xs text-slate-500`，值 `text-3xl font-bold`（状态色 text），副行 `text-xs text-slate-400`。
- 指标名上方可加一个迷你带宽示意条（`▁▂▃▅▃▂▁`），位置值与当前值落在哪一段用状态色高亮。

#### 指标口径 / 公式 / 阈值

| 指标 | 公式 | 单位 | 绿(健康) | 黄(关注) | 红(预警) |
| --- | --- | --- | --- | --- | --- |
| 管理幅度 | 非管理者人数 ÷ 管理者数（管理者 = 有 `leaderName` 的部门负责人去重） | 人 | 3–8 | 1–3 或 8–12 | <1 或 >12 |
| 层级深度 | 组织树最大深度（L1 为 1，逐层 +1） | 层 | 1–4 | 5–6 | ≥7 |
| 管理者比 | 管理者数 ÷ 总人数 | % | ≤15% | 15–25% | >25% |
| 空岗率 | (编制 − 实际) ÷ 编制（编制缺省时按 0 处理并标注） | % | ≤10% | 10–20% | >20% |

#### 一句话判读（文案模板，状态对应）

| 指标 | 健康 | 关注 | 预警 |
| --- | --- | --- | --- |
| 管理幅度 | 「管理幅度适中，层级健康」 | 「管理幅度偏窄/偏宽，建议优化汇报线」 | 「管理幅度失衡，存在失控或冗余风险」 |
| 层级深度 | 「层级精简，决策链短」 | 「层级偏深，可考虑扁平化」 | 「层级过深，决策效率低，建议压缩」 |
| 管理者比 | 「管理者占比合理」 | 「管理者占比偏高，注意成本/官僚倾向」 | 「管理者占比过高，存在头重脚轻」 |
| 空岗率 | 「编制基本满编」 | 「空岗率偏高，关注招聘节奏」 | 「空岗严重，影响业务交付」 |

#### 判读汇总区

- 顶部一行：`红 0 · 黄 1 · 绿 3`（带状态点，从 4 指标聚合）。
- 一句整体诊断（模板，基于非绿数量）：
  - 全绿：`「整体健康度良好，组织结构稳健。」`
  - 有黄无红：`「整体健康，部分指标需持续关注。」`
  - 有红：`「存在明显异常（X 项预警），建议优先治理。」`
- 右侧【生成诊断建议】按钮 → 打开 Feature D 诊断报告（预填当前场景指标），并可选把建议文案复制进报告。

### 1.7 L3 编制 vs 实际 vs 缺口（含成本）

**表格**（`w-full text-sm`，玻璃容器内）：

| 列 | 说明 |
| --- | --- |
| 部门 | 部门名（L1 或叶子部门） |
| 编制 | 编制人数（`headcount`，缺失显示「—」） |
| 实际 | `employees.length` |
| 缺口 | 编制 − 实际（负数→超编；正数→空岗）；单元格按正负给状态色 |
| 平均成本 | 部门平均月成本（`avgCost` 或由职级成本映射聚合） |
| 实际成本 | 实际人数 × 平均成本 |
| 缺口成本 | 缺口 × 平均成本（正=待补薪资预留，负=超编成本） |

- 表格头：`text-xs text-slate-400 uppercase tracking-wide border-b border-slate-100`。
- 行：`border-b border-slate-50 hover:bg-slate-50/60`。
- 缺口列：负数用 `text-red-600`（超编/成本超支），正数用 `text-amber-600`（空岗待补），补文字标签「+4 空岗」/「-4 超编」。
- 表格下方配**条形对比**：每行部门「编制」与「实际」双条，`编制`= 灰色淡条（`bg-slate-200`），`实际`= 状态色条（满编绿/超编红/空岗黄），并存 `title` 提示。

**空态**：若全部部门未配置 `headcount`/成本 → 显示「未配置编制与成本数据」+「去配置」按钮（跳转 Sidebar 编制配置区 / 打开职级成本配置弹窗）。

## 2. Feature B — 项目 / 场景管理 + 保存状态

### 2.1 领域模型

```
.orgproj（项目文件） = {
  id, name, version,
  currentScenarioId,
  scenarios: Scenario[],       // 多个场景快照
  meta: { createdAt, updatedAt }
}
Scenario（场景快照） = {
  id, name, createdAt, updatedAt,
  departments: Department[],       // 组织树
  levelConfigs: LevelConfig[],
  headcountCost: {                 // 编制/成本配置（见 0.2）
    deptHeadcount: Record<deptId, number>,
    levelCost: Record<fullCode, number>,
  },
  canvas: { zoom, lastFocusedDeptId? }
}
```
- **一个工作区 = 一个 `.orgproj` = 一个工作区 + 多场景快照**。
- 场景用于**演练对比**：例如「现状」「调优方案A」「调优方案B」，用户在各场景间切换查看差异，互不覆盖。
- 持久化：浏览器版 `localStorage`；Tauri 版可存 `.orgproj` 文件（`saveFile` 复用）。

### 2.2 TopBar 信息结构（改造后）

三区布局，项目身份信息靠左，全局命令靠右：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ [◇ 组织架构设计 v2.0.2]  [项目名·基线▾] [●已保存 12:30]   …  [工具模板▾][健康度][缩放][撤销][重做][职级管理] │
└─────────────────────────────────────────────────────────────────────────────┘
```

**左区（项目身份 + 场景切换）**：
- 品牌 Logo + 组织架构设计 + 版本徽章（更新为 `v2.0.2`）。
- **项目名 + 场景切换器**：一个复合控件，主体显示当前场景名，右侧 `▾`。
  - 点击 ▾ → 打开**场景切换下拉**（见 2.4）。
- **保存状态指示**（见 2.5）。

**右区（全局命令）**：补齐 `[工具模板▾] [健康度] [缩放控件] [撤销] [重做] [职级管理]`。撤销/重做见 Feature C。

> 空间建议：若右区过挤，将【健康度】与【职级管理】并入一个「更多▾」菜单或保持分级；但**健康度**是 v2.0.2 核心能力，建议常驻可见。

### 2.3 场景切换器（折叠态 + 展开态）

**折叠态**（胶囊）：
```
[ 场景: 基线 ▾ ]     ← 显示当前场景名（点按或悬停展开）
```
- 样式：`flex items-center gap-1.5 px-3 py-1.5 rounded-xl bg-slate-100/80 border border-slate-200/60 hover:bg-white text-sm text-slate-700`（沿用缩放控件条样式，语义统一）。
- 当前场景名 `font-semibold`，`ChevronDown` 旋转。

**展开态（下拉）**：
```
┌── 场景 ────────────────────────────────┐
│  基线                    [●]  (当前)     │
│  调优方案A                              │
│  调优方案B                              │
│  ─────────────────────────           │
│  [+ 新建场景]  [复制] [重命名] [删除] [管理场景] │
└───────────────────────────────────────┘
```
- 面板：`absolute left-0 top-full mt-2 w-72 rounded-2xl bg-white/90 backdrop-blur-xl border border-slate-100 shadow-xl p-2 z-50 animate-fadeInUp`。
- 场景项：`flex items-center justify-between px-3 py-2 rounded-xl hover:bg-indigo-50`；当前场景右侧带 `●` 状态点 + 显示更新时间 `text-xs text-slate-400`。
- 底部操作行（见 2.4）。

### 2.4 新建 / 复制 / 重命名 / 删除场景

| 操作 | 触发 | 交互与反馈 |
| --- | --- | --- |
| 新建场景 | 下拉「+ 新建场景」 | 弹一个小输入框（inline 或弹窗）输入场景名，默认名 `场景 N`；创建后**复制当前场景快照**为起点，切换到新场景；toast「已创建场景「调优方案C」」 |
| 复制场景 | 选中场景 → 「复制」 | 生成 `「{原名} 副本」`，不影响原场景 |
| 重命名 | 选中场景 → 「重命名」 | 改名输入框，Enter 提交，Esc 取消；重复名校验（弱警告） |
| 删除场景 | 选中场景 → 「删除」 | `confirm`「确定删除场景「调优方案B」？此操作不可恢复」；**禁止删除最后一个场景**；删除后自动切换到剩余某个场景 |
| 管理场景 | 「管理场景」 | 打开**项目管理弹窗**（见 2.6），集中管理 + 保存/另存 `.orgproj` |

**切换场景**：点击场景项 → 无缝切换（画布数据替换为对应 `scenario.departments`），保留 zoom；切换前若有未保存更改自动保存。

### 2.5 保存状态指示（与自动保存融合）

三种互斥状态，左侧项目名旁常驻：

| 状态 | 视觉 | 说明 |
| --- | --- | --- |
| 已保存 | `● 已保存 12:30`（emerald 点 + 最近保存时间） | 数据已落盘；时间用 `HH:mm` |
| 保存中 | `○ 保存中…`（旋转 spinner + 灰字） | 自动保存 debounce 期间 |
| 有未保存更改 | `● 未保存更改`（amber 点） | 用户作了改动未落盘 |

- **自动保存**：任何会改 `departments` / `levelConfigs` 的动作触发 `debounce(800ms)` 保存到当前场景 + 更新 `updatedAt`。保存成功后置为「已保存」+ 刷新时间。
- 保存失败：置为「保存失败 重试」点击类（红字 + 点击重试）。
- 提示信息放 `<span className="text-[10px] text-slate-400">`（与版本徽章同一字体层级），避免喧宾夺主。

### 2.6 项目管理弹窗（集中管理 + 文件）

- 形态：居中弹窗（复用 `LevelManagerModal` 结构：遮罩 + `max-h-[85vh] rounded-3xl bg-white/90 backdrop-blur-xl shadow-2xl animate-fadeInUp`，`w-[640px]`）。
- 内容分区：
  1. **项目信息**：项目名（可编辑）、创建/更新时间、版本。
  2. **场景列表**：同 2.3 的列表 + 增删改复制操作（复用）。
  3. **文件**：【另存为 .orgproj】/【导入 .orgproj】（Tauri 走 `saveFile`/`openFile`，浏览器走下载/上传）。
- 说明文案：`text-xs text-slate-400`「保存为 .orgproj 项目文件，便于备份与分享」。

## 3. Feature C — 撤销/重做 + 批量选择移动

### 3.1 撤销/重做

**驱动**：命令模式 / 快照栈。任何会变更 `departments`（或 `levelConfigs`、编制成本）的**用户动作**在变更前压栈。

**快捷键**：
- 撤销：`Ctrl/Cmd + Z`
- 重做：`Shift + Ctrl/Cmd + Z`（兼容 `Ctrl/Cmd + Y`）

**按钮**：TopBar 右区加两个图标按钮 `Undo2` / `Redo2`（lucide，w-4 h-4），置于缩放控件旁。样式与缩放按钮一致（icon 按钮 `text-slate-600 hover:bg-white`），无历史时 `disabled:opacity-40`。

**栈策略**：
- 以**快照**存整棵 `departments`（含 `expanded`/结构），简单可靠；或用「逆操作」保持内存。推荐快照（数据量小）。
- 压栈时机：`handleToggleExpand` / `handleUpdateDepartment` / `handleUpdateLeader` / `handleMoveEmployee` / `handleMoveDepartment` / `handleCreateDepartment` / `handleChangeDepartmentLevel` / `handleCreateVirtualEmployee` / `handleDeleteEmployee` / 批量移动。**缩放、展开/收起**可选入栈（推荐展开/收起也入栈，便于撤销误点）。
- 撤销后联动刷新健康度中心与画布（state 驱动，自动）。
- 撤销一步后若用户又做新动作 → 清空 redo 栈（标准行为）。可推 toast「已撤销」/「已重做」。

### 3.2 批量选择（框选 vs 逐点）

**推荐：框选（marquee）为主 + 逐点（点击/Shift 点击）为辅**，符合组织图画布直觉（类 Figma/白板）。

| 方式 | 触发 | 行为 |
| --- | --- | --- |
| **框选** | 在**空白画布**上按住左键拖出矩形 | 选中与矩形相交的**部门卡片**（或员工标签）。仅在空白区（非卡片上）启动，避免与现有 dnd-kit 拖拽部门冲突 |
| 逐点单选 | 点击某部门卡片 | 单击选中该卡（取消其他选中）；再次点击取消 |
| 追加/减选 | `Shift/Cmd + 点击` | 切换该卡的选中态（不会取消已有选中） |
| 清空 | 点击空白 / 按 Esc | 清空当前选中集 |

**选中态视觉**：选中卡片加外描边 + 淡光晕：`ring-2 ring-indigo-400` + `shadow-tint` + 轻微上浮 `-translate-y-0.5`（用 CSS 类控制，不在卡片上加全局响应式逻辑）。员工标签选中：`ring-1 ring-indigo-300`。

**选中浮动工具条**（出现于画布顶部或选中区上方）：
```
[ 已选 3 个部门 ]  [移动] [删除] [撤销选择]
```
- 显示选中数量 `text-xs`。
- 移动 = 拖拽其中之一（或点「移动」后需拖到目标）→ 批量移动全部选中（见 3.3）。
- 删除 = 批量删除选中（`confirm` 提示影响）。
- 撤销选择 = 清空。

### 3.3 批量移动 + 视觉反馈

**移动方式**：在选中集中，**拖拽任意一个**选中卡片到目标部门（或空白=根级），带动**整个选中集**一起移动，目标结构按「整棵子树移动」处理。

**位移规则**：把选中的 N 个部门（及其子树）整体挂到目标部门下（level 自动 +1 重算），并在结构上保持相对顺序。若目标为空 / 根级 → 全部升为根级。

**视觉反馈**：
1. **拖拽中**：选中集整体以「半透明跟随」显示（`opacity-70`），每张卡保留选中描边；目标部门（`useDroppable`）出现 `ring-2 ring-indigo-400 bg-indigo-50/50` 高亮。
2. **落地**：短暂**涟漪/高亮闪**（`target` 卡 `ring` 闪 400ms）+ 全选取消；底部 toast「已移动 3 个部门到「研发组」」。
3. **可撤销**：该批量移动压入 undo 栈，Ctrl+Z 可整体回退。
4. **合法性**：禁止把部门移动到自身/其后代（沿用现有 `isDescendant` 校验）；出现则 toast 提示且不动。

> 冲突规避：框选在**空白区**启动（`onPointerDown` 判断 `e.target` 是否在画布背景），部门拖拽在**卡片上**启动（现有 dnd-kit `PointerSensor`）。二者通过启动区域区分，互不干扰。拖拽选中集中的卡片时仍需满足 dnd-kit 的 `distance:8` activation，避免误触。

## 4. Feature D — 汇报导出（诊断报告页面）

### 4.1 形态

**独立报告视图**（非裸画布）：一个全屏覆盖层 / 视图，用于**对外汇报**。入口 = 健康度抽屉头部【导出诊断报告】按钮 + 侧边栏【导出】区新增「诊断报告」。

- 形态：`fixed inset-0 z-[90] bg-white/95 backdrop-blur-lg overflow-y-auto`（白底为主，弱化玻璃感，便于打印/导出），或作为视图切换覆盖 `main`。
- 顶部工具条（吸顶，`sticky top-0 bg-white/80 backdrop-blur border-b border-slate-100`）：
  ```
  [← 返回编辑]   诊断报告 · 「技术部调优方案」    场景：基线 | 生成：2026-08-23 12:30   [打印/导出PDF] [导出PNG]
  ```

### 4.2 报告正文结构（自上而下）

```
┌ 报告头部 ─────────────────────────────────────────────┐
│ 组织架构诊断报告                                        │
│ 项目：xxx   场景：基线   生成时间：2026-08-23 12:30     │
└──────────────────────────────────────────────────────┘
┌ 摘要指标卡（一行 5 卡）───────────────────────────────┐
│ [整体健康度 ●良好] [总人数 47] [部门数 12] [编制缺口 +6] [月人力成本 286w] │
└──────────────────────────────────────────────────────┘
┌ 健康度指标（4 卡，复用 L2 指标）───────────────────────┐
│ [管理幅度][层级深度][管理者比][空岗率] + 一句整体诊断     │
└──────────────────────────────────────────────────────┘
┌ 组织架构图（只读非交互，稍缩放适配页面）────────────────┐
│  ┌─ 嵌入 OrgChart readOnly ─┐        （自动缩放 fit 页面宽）│
└──────────────────────────────────────────────────────┘
┌ 部门明细表 ──────────────────────────────────────────┐
│ 部门|层级|负责人|人数|编制|缺口|职级分布摘要            │
│ (逐行)                                                  │
└──────────────────────────────────────────────────────┘
┌ 诊断建议（可选，来自 L2 判读生成）────────────────────┐
│ • 空岗率偏高的部门建议优先补充……                         │
└──────────────────────────────────────────────────────┘
```

### 4.3 关键设计点

- **摘要指标卡**：`grid grid-cols-5 gap-4`，每卡 `rounded-2xl bg-white border border-slate-100 shadow-soft p-4`，值大号 `text-2xl font-bold`，标签 `text-xs text-slate-500`。整体健康度卡状态色（绿/黄/红）。
- **组织图嵌入**：复用 `OrgChart` 的布局逻辑，但设 `readOnly`（`pointer-events-none` 禁拖拽/编辑/右键），用一个 `fit` 计算自动缩放到页面宽（`@media print` 时缩放到适合一页）。实现上可为 OrgChart 加 `readOnly` prop，或抽公共布局。**建议用 `readOnly + 自动 fit 缩放`**，保持图表一致性与可复用。
- **部门明细表**：直接取 `Department` 扁平化，含「职级分布摘要」（如 `L1×5, L2×8, L3×2`）。
- **诊断建议**：由 L2 判读生成一段可编辑文本（默认生成，用户可改），存入场景。

### 4.4 打印 / 导出样式（`@media print`）

```css
@media print {
  body { background: #fff !important; }
  .no-print { display: none !important; }   /* 顶部工具条、交互控件 */
  .report-section { break-inside: avoid; }  /* 指标卡/图表不跨页切断 */
  .report-orgchart { break-inside: avoid; page-break-inside: avoid; }
}
```
- **导出 PDF**：无 pdf 依赖，用 `window.print()`（浏览器 → 另存为 PDF），配 `@media print` 隐藏交互元素。
- **导出 PNG**：`html2canvas`（已装于项目），对报告视图渲染为 PNG（透明/白底，`backgroundColor:'#FFFFFF'`，scale 2）。
- 导出按钮处理 Tauri：PNG 走 `saveFile`，PDF 可调 Tauri 打印器或浏览器打印。

### 4.5 报告与场景联动

- 报告的「场景：基线」标记来源场景；若用户切换场景，报告头部场景名随之更新（报告基于当前场景数据渲染）。
- 报告生成可被「保存到场景」作为一次快照，便于日后回看。

### 5.1 需要新增的 Tailwind 资源（建议注册到 `tailwind.config.js`）

当前 `tailwind.config.js` 为 `theme.extend:{}`，`shadow-soft/card/tint` 类实际**未定义**（为 no-op）。建议注册：

```js
theme: {
  extend: {
    boxShadow: {
      soft: '0 2px 15px -3px rgba(0,0,0,.07), 0 10px 20px -2px rgba(0,0,0,.04)',
      card: '0 1px 3px rgba(0,0,0,.06), 0 8px 24px rgba(99,102,241,.08)',
      tint: '0 12px 30px rgba(99,102,241,.12)',
    },
    keyframes: {
      slideInRight: { from: { transform: 'translateX(100%)', opacity: 0 }, to: { transform: 'translateX(0)', opacity: 1 } },
      slideInUp: { from: { transform: 'translateY(24px)', opacity: 0 }, to: { transform: 'translateY(0)', opacity: 1 } },
    },
    animation: {
      slideInRight: 'slideInRight 0.24s ease-out',
      slideInUp: 'slideInUp 0.3s cubic-bezier(0.4,0,0.2,1)',
    },
  },
}
```
> 若不想改配置，可退回任意值（如 `shadow-[0_8px_24px_rgba(99,102,241,0.08)]`、`animate-[slideInRight_0.24s_ease-out]`），但推荐注册以便复用。
